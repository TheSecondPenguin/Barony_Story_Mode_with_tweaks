# Blind playtest feedback

No custom playable build or completed playtest is recorded at bootstrap. Do not ask the player to install a source patch or overwrite an existing game installation.

When a verified test build is available, give the player only its safe build identifier, launch instructions, expected test duration and tested capabilities. Request a short session first, with longer play only if comfortable. Stopping early is useful evidence, not a failed participant.

## Feedback template

- Safe build ID and test date:
- OS, display size/resolution/refresh rate and input device:
- Local execution or remote display:
- Enabled comfort settings:
- Approximate session length and when discomfort began, if any:
- Movement/action around that time, described without guessing a cause:
- Could you understand controls and important audiovisual feedback?
- Did your choices and class feel distinct and useful?
- Could all participants follow the action and contribute?
- Did returning or resuming behave as expected?
- Opaque issue ID, if one was shown:

Do not request secret names, future outcomes, solutions, hidden conditions, screenshots or raw logs. If the player voluntarily describes a discovery, handle that context internally and keep follow-up reports spoiler-safe. Ask about clarity, agency, tension and cooperation without revealing the intended answer.

## Received observations

No runtime feedback has been verified in this checkout. Preserve later observations in dated entries, including the tested build and session context. Keep symptoms separate from hypotheses and from measured improvements; do not diagnose motion discomfort from perspective alone.
